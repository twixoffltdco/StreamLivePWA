# Stream Live PWA

Единый PWA-интерфейс для телефонов, планшетов и совместимых ТВ-устройств. Это именно PWA-проект: лендинг находится на `/`, каталог — на `/app`, экран выбранного материала — на `/app/watch/[id]`.

## Источники

- `https://domtv.blyz.ru`
- `https://streamlivetv.freedev.app`
- `https://streamliveru.web1337.net`

Каталог объединяет материалы, которые удалось получить с каждого источника. Элементы хранят исходный URL и идентификатор источника. Одинаковые материалы на разных зеркалах не удаляются: карточки каждого источника остаются отдельными. Фильтры каталога разделяют каналы, видео, форум и прочие материалы.

## Архитектура

- `app/page.tsx` — лендинг Stream Live PWA.
- `app/app/page.tsx` и `components/CatalogApp.tsx` — единая лента, поиск, фильтры источника и типа контента, избранное и диагностика источников.
- `app/api/catalog/route.ts` — собирает результаты трёх источников параллельно и возвращает карточки вместе с диагностикой каждого источника.
- `lib/scraper.ts` — серверный HTML-парсер на Cheerio. Идентификатор карточки включает источник, поэтому дубли между зеркалами сохраняются. Порядок отображения источников: production (`freedev.app`), резерв (`domtv.blyz.ru`), третье зеркало (`web1337.net`).
- `app/api/video/route.ts` — получение метаданных отдельной страницы в пределах разрешённого источника. Для известных `channel.php?slug=...` и `video.php?slug=...` формируется адрес соответствующего embed-плеера.
- `app/app/watch/[id]/page.tsx` — отдельный экран просмотра с переходом на оригинальный источник.

## Важно про доступность сайтов

Серверный загрузчик умеет обрабатывать используемые этими тремя источниками простые cookie/PoW-проверки, а парсер получает HTML только через серверный runtime. TLS-проверка по умолчанию строгая; для сертификатной ошибки предусмотрен ограниченный повтор только к трём явно перечисленным зеркалам. Это временная совместимость, а не замена исправному TLS-сертификату. API возвращает диагностику отдельно по каждому источнику — HTTP-статус, время ответа, число карточек и текст ошибки. Если структура сайта изменилась, селекторы нужно адаптировать по свежему HTML.

## Локальный запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. Production-сборка:

```bash
npm run build
npm start
```

Приложение должно работать на хостинге с Node.js/Next.js runtime, чтобы выполнялись маршруты `/api/catalog` и `/api/video`. Обычный статический хостинг без серверных маршрутов не сможет выполнять Cheerio-парсер.

## PWA и управление

- `public/manifest.json` задаёт режим установки PWA.
- Установку и шаги установки обслуживают компоненты `InstallButton` и `InstallSteps`.
- Элементы интерфейса поддерживают навигацию с клавиатуры и ТВ-пульта.
- Совместимость установки зависит от браузера и устройства.

## Сборка на Layero

Убедитесь, что приложение собрано в режиме Next.js server/standalone, а не статического экспорта. Команды: `npm install` и `npm run build`; старт: `npm start` (либо команда, предусмотренная конфигурацией Layero). В этой сборке lock-файл намеренно не включён, потому что старый `package-lock.json` не содержал `cheerio` и не совпадал с `package.json`. Удали старый `package-lock.json` из Git-репозитория при замене файлов; Layero должен выполнить `npm install`. Для воспроизводимых установок после успешной сборки создай новый lock командой `npm install` и закоммить его вместе с `package.json`.


### Каталог: фильтрация и объединение каналов

- Служебные страницы, навигационные заголовки и технические ответы отбрасываются при сборе.
- Каналы с совпадающими нормализованными названиями объединяются в одну карточку. Все доступные зеркала остаются в карточке и доступны в выборе источника на странице просмотра.
- Каталог группируется по production и зеркалам; видео и форумные материалы не склеиваются между источниками.
